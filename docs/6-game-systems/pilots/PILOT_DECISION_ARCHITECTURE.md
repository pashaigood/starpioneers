# Архитектура принятия решений пилота

## Обзор

Система принятия решений пилота полностью переработана и теперь основана на чистом **Behaviour Tree (дереве поведения)**.

## Принципы

### 1. Разделение ответственности

- **PilotModel** - только данные пилота (статистика, потребности, инвентарь). Не содержит логики принятия решений.
- **PilotGoalPlanner** - ЕДИНСТВЕННЫЙ источник логики принятия решений. Анализирует состояние пилота и возвращает цель.
- **GoalQueue** - простое хранилище текущей цели и её выполнение. Не принимает решений о прерывании.
- **BTNode** - узлы дерева поведения (Condition, Action, Selector) - чистая структура без side-effects.

### 2. Линейный поток

```
PilotModel.Simulate()
  ↓
  1. Обновить потребности (Needs.UpdateNeeds)
  ↓
  2. Обновить базовое состояние (усталость, мораль, навыки)
  ↓
  3. Получить корабль (если назначен)
  ↓
  4. ПРИНЯТИЕ РЕШЕНИЯ: planner.EvaluateAndSetGoal(pilot, ship)
     - Оценивает дерево поведения
     - Возвращает желаемую цель
     - Сравнивает с текущей целью
     - При необходимости прерывает и устанавливает новую
  ↓
  5. Выполнить текущую цель: Goals.ExecuteCurrentGoal()
```

### 3. Дерево поведения (Behaviour Tree)

Структура дерева в `PilotGoalPlanner.EnsureTreeBuilt()`:

```
SelectorNode (выполняет первый успешный дочерний узел)
├─ ConditionNode: Health < 20%
│  └─ ActionNode: PlanEmergencyHealing
│
├─ ConditionNode: Fatigue > 95%
│  └─ ActionNode: PlanRest
│
├─ ConditionNode: Ship needs service (refuel/repair)
│  └─ SelectorNode
│     ├─ ConditionNode: Need == Refuel
│     │  └─ ActionNode: PlanRefuel
│     │
│     └─ ConditionNode: Need == Repair
│        └─ ActionNode: PlanRepair
│
└─ ActionNode: PlanForMostUrgentNeed
   (анализирует потребности и планирует соответствующую цель)
```

### 4. Типы узлов дерева

- **ConditionNode** - проверяет условие `(PilotModel, ShipModel) => bool`, если true - выполняет дочерний узел
- **ActionNode** - выполняет функцию `(PilotModel, ShipModel) => Goal` и возвращает цель
- **SelectorNode** - перебирает дочерние узлы и возвращает первый успешный результат (не null)

## Удалённые компоненты

Следующие компоненты были **полностью удалены** как избыточные:

- ❌ `ApplyAndInterruptNode` - логика прерывания теперь в `EvaluateAndSetGoal`
- ❌ `PrioritySelectorNode` - избыточно, используется обычный `SelectorNode`
- ❌ `PlanHungerNode`, `PlanComfortNode`, `PlanEntertainmentNode`, etc. - заменены на простые методы в `PilotGoalPlanner`
- ❌ `GoalNode` - избыточная обёртка
- ❌ Вся логика подписки на события корабля из `PilotModel` - упрощено
- ❌ `CurrentAttackers` и `AttackerTypes` - боевая логика упрощена
- ❌ Очередь целей из `GoalQueue` - теперь хранится только одна текущая цель

## Ключевые методы

### PilotGoalPlanner.EvaluateAndSetGoal

Основной метод планировщика:

1. Если очередь пуста - оценивает дерево и устанавливает новую цель
2. Если цель уже есть:
   - Оценивает дерево снова
   - Если новая цель имеет больший приоритет И текущую можно прервать → прерывает и устанавливает новую

### Методы планирования

Каждая потребность имеет свой метод планирования:

- `PlanEmergencyHealing` - критическое здоровье → медицинский модуль
- `PlanRest` - усталость → бар или магазин
- `PlanRefuel` - топливо корабля → заправка
- `PlanRepair` - ремонт корабля → верфь
- `PlanHunger` - голод → купить еду
- `PlanComfort` - комфорт → бар
- `PlanEntertainment` - развлечения → казино/бар
- `PlanSelfActualization` - самореализация → торговля
- `PlanTradeOrWander` - низкая срочность → торговый маршрут или случайное движение

## Приоритеты

Порядок проверки условий в дереве = порядок приоритетов:

1. **Критическое здоровье** (< 20%) - наивысший приоритет
2. **Критическая усталость** (> 95%)
3. **Потребности корабля** (заправка/ремонт)
4. **Личные потребности** (по срочности)

## Преимущества новой архитектуры

✅ **Линейность** - понятный поток выполнения без скрытых вызовов
✅ **Единственный источник решений** - вся логика в `PilotGoalPlanner`
✅ **Легко расширяемо** - добавить новое условие = добавить узел в дерево
✅ **Без side-effects в узлах** - узлы только возвращают Goals, не меняют состояние
✅ **Простота отладки** - можно логировать каждое решение дерева
✅ **Нет избыточности** - убрана вся дублирующаяся логика

## Как добавить новое условие/потребность

1. Создать метод планирования в `PilotGoalPlanner` (например, `PlanNewNeed`)
2. Добавить узел в дерево в `EnsureTreeBuilt()`:
   ```csharp
   new ConditionNode(
       (p, s) => /* условие */,
       new ActionNode((p, s) => PlanNewNeed(p, s))
   )
   ```
3. Готово! Дерево автоматически учтёт новое условие при следующей оценке.
