Planet UI - Полноэкранная карточка при посадке

Коротко: при посадке игрока на планету открывается полноэкранная карточка планеты. Она концентрируется на сервисах станции и быстрых действиях (заправка, ремонт, верфь), даёт полный список услуг и возможность смотреть детали каждой услуги без лишних кликов.

Основное поведение​

  • Событие открытия: Player.DockedAt(planetId) → открыть Planet Card (full-screen).
  • Карточка блокирует остальные элементы HUD и фокусирует внимание на сервисах/действиях.
  • Все операции, меняющие мир (покупка, заправка, ремонт), выполняются атомарными вызовами CelestialModel и дают явную обратную связь.

Структура экрана (кратко)​

  • Header (фиксированный) - название, бейджи (пригодность, специализация, фракция, статус отношений), кредиты игрока, кнопка "Взлёт".
  • Левая панель - крупный визуал планеты (3D-превью / видеопетля) + основные статы.
  • Правая панель - список сервисов (верфь, заправка, ремонт, рынок, миссии, бар) + панель деталей (динамическая).
  • Persistent Quick Actions - всегда доступная панель быстрых действий (Взлёт, Быстрая заправка, Быстрый ремонт, Открыть верфь, Открыть рынок).
  • Activity/Receipt - нижняя полоса с журналом транзакций и undo.

Стиль интерфейса - соответствие Assets/UI/simple.uss / simple.uxml​

Мы ориентируемся на существующий минималистичный HUD в Assets/UI/simple.uss и структуру simple.uxml. Практические правила интеграции:

  1. Цвета и типографика

    • Основные цвета: фон - тёмный (#000..#222), текст белый; CTA - акцент (electric cyan или #00E5FF); успех - зелёный; ошибка - красный.
    • Шрифты: те же семейства, что рекомендованы в simple.uss (Orbitron / Exo 2 / Space Grotesk / Montserrat). H1 (название) 28-34px, сервисный заголовок ~18px, тело ~14px.

  2. Поведение контролов и анимации (в духе simple.uxml)

    • Быстрые кнопки оформлять как Button с классом speed-button (малый padding, border-radius 4).
    • Полосы и круговые индикаторы - визуальные элементы без pointer events (например, .fuel-arc), управляемые контроллером.
    • Использовать те же трансформации/анимации: subtle zoom при открытии, slide-up для деталей, translateY для hover эффектов.

  3. UI Toolkit практики

    • Инспектируемые стили подключать через <Style src="...simple.uss#simple" /> как в simple.uxml.
    • Именовать кнопки/элементы (name атрибут) - это важно для контроллеров (PlayerUIController, PlanetCardController).
    • Во view-model писать только snapshot данных, UI читать snapshot без блокировок продолжительное время.

  4. Практические примеры (рекомендации для реализации)

    • Для индикатора топлива: создать rad:RadialSlider с name="fuel-radial" в Planet Card - контроллер обновляет value = ShipModel.FuelPercent.
    • Для быстрых пресетов заправки: кнопки с классом .speed-button, при нажатии открыть inline-попап с prefilled суммой и кнопкой подтверждения.
    • Для списка верфи: reuse simple.uss grid spacing, иконки 24/32px, каждая карточка сервиса - VisualElement с классом .service-tile (в стиле .speed-button + иконка).
    • Для журнала/чеков: использовать небольшой фиксированный контейнер по аналогии с .hud-root (нижний левый/нижний центр), класс .activity-log.

UX: ключевые сценарии (игровой фокус)​

  • Взлёт (Takeoff): CTA в Header; при нажатии - модал подтверждения с проверкой топлива/ремонта; если плохо - предлагать быстрые действия (Refuel, Repair).
  • Быстрая заправка / ремонт: 1-2 клика, inline подтверждение, мгновенный receipt.
  • Верфь (Ship Shop): просмотр, сравнение, покупка - все в рамках карточки; транзакция вызывает Market.TryBuy и логирует чек.
  • Отображение отношений с фракцией: бейдж в Header показывает фракцию и краткий статус (Friendly/Neutral/Hostile) + tooltip с подробностями.

Технические замечания (повтор)​

  • UI читает snapshot под lock(model.Sync) единожды, затем работает с view-моделью; подписки на события Market/Service только при открытой карточке.
  • Для транзакций применять optimistic UI с откатом при ошибке (undo toast 5-10s).
  • Поддерживать accessibility: уменьшение анимаций, масштаб текста, keyboard shortcuts (T/F/R/M/S).

Краткий список рекомендаций для разработчика UI​

  • Переиспользовать классы из simple.uss (speed-button, hud-root, top-left-hud, health-container, radial-root).
  • Добавить Assets/UI/planet_card.uxml и Assets/UI/planet_card.uss, подключив simple.uss и расширив стили.
  • Создать PlanetCardController.cs:
    • Подписка: Open/Close, Bind(snapshot), QuickAction handlers (Refuel, Repair, Shop), Takeoff handler.
    • Вызовы: planet.ProvideRefuel(...), planet.ProvideRepair(...), Market.TryBuy(...).
    • Обновление radial fuel: fuelRadial.value = ShipModel.CurrentFuel / ShipModel.MaxFuel * 100.
  • Именовать элементы (имена) для лёгкого поиска в контроллере (например: btnTakeoff, btnRefuel25, fuel-radial, creditsLabel, factionBadge).

Acceptance criteria (обновлено)​

  • Планетная карточка использует визуальный язык и классы из simple.uss и выглядит согласованно с существующим HUD.
  • Быстрая заправка, быстрый ремонт и кнопка "Взлёт" доступны за 1-2 клика и используют существующие USS-стили.
  • В Header отображаются фракция и кредиты игрока (имя и сумма), оформлены в стиле simple.uss.
  • Контроллеры именуют элементы так, чтобы автоматические тесты могли найти кнопки/labels по имени.
